# 证书目录

跟 `data/rules.json`、`data/plugins.json` 一样：**随包分发、进版本库**，装到哪台机器都带着。

## `ca-bundle.pem`

Mozilla 根证书集（取自 <https://curl.se/ca/cacert.pem>），仓库自带的那份兜底 CA。

用它的场景只有一个：宿主环境里一个 CA 包都没有（精简容器、没装 `ca-certificates` 的
Alpine 等）。探测顺序是 `环境变量 → 系统路径 → certifi → 这份`，也就是说**平时轮不到它**
——系统那份（还可能含企业根）优先。它的价值是：这种情况下仍然**严格校验证书**，
而不是过去那种"为了能用就把全站校验关掉"。

更新：重新下载覆盖即可（`curl -o ca-bundle.pem https://curl.se/ca/cacert.pem`）。

## `extra/` —— 站点专有证书

**投放点是用户目录 `~/.webtool/certs/extra/`**（跟 `WEBTOOL_DIR` 环境变量走）。
某个站的证书不在公共信任根里（自签），把它的 `.pem` / `.crt` 丢进那儿，
再**按站点配一条规则**，该站就走"正常校验 + 这套只对它生效的信任根"，
不必 `verify_hosts` 关校验、更不必 `verify=False`：

```json
{"kind": "tls", "match": {"domain": ["zce.com.cn", "*.zce.com.cn"]},
 "ca": "extra/zce.pem"}
```

规则不用手写：`webtool proxy cert sync` 会读每份证书自称的域名（SAN / CN），
把规则自动写进 `rules.json`；`webtool proxy cert list` 看现状
（证书 → 覆盖哪些站点 → 顶上有没有规则 → 过期时间）。

**为什么非要那条规则**：证书是*某个站点的*证书，信任根就该只对它生效。
早先是"放进 extra/ 就全局并进信任根"，一份站点自签证书顺手给所有域名开了口子
——企业 MITM 根一旦丢进去，全站就都认它了。现在没规则的证书**不生效**，
`webtool config list` 会点名提醒。

- 只放证书本身，不要放私钥。
- 命中规则的域名才现拼一份"基础 CA + 该站证书"的合并文件（缓存在 `cache/tls/`）；
  没命中一分钱不多花。
- 规则里的 `ca` 支持相对路径（`extra/zce.pem` = `~/.webtool/certs/extra/zce.pem`），
  换机器、换 home 都还认；写死绝对路径的规则一换环境就整批失效。
- 规则里的 `ca` 是**追加**语义（基础 CA + 该站证书），与全局 `ca_bundle` 的
  "替代"语义相反：站点证书只对自己有意义，没理由把公共根挡在外面。

包内这个 `extra/` 目录是**发行方预置**的（同名时用户目录那份胜出），
空目录不进 wheel，装完不会存在，别往里放用户数据 —— 实测往包目录塞的证书
`pip install --upgrade` 之后片甲不留，表现成"某个站的证书突然又报错了"。

放进去前先确认**值得放**：证书校验失败先看 webtool 给的类别——

| 类别 | 证书 + 规则能修吗 |
|---|---|
| 自签证书 | ✅ 能 |
| 证书过期 / 与域名不符 | ❌ 不能：换信任根也修不了"过期"和"名字不对"（要用就 `verify: off` 单独关该站） |
| 上游没发中间证书 | ❌ 不能：得用 `ca_bundle` 补中间证书 |
