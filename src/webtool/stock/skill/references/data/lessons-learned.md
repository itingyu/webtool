## 通用经验

### 1. 海外是背景，A 股是主语

外盘是必要不充分条件。任何"外盘 X → A 股 Y"后必须加"需结合 A 股内因二次确认"。

### 2. 板块要分"指数 vs 个股"两层

两者背离时不能说"板块走强 / 走弱"，必须说"分化"。追涨难度：指数+个股都强 < 指数强+个股分化 < 指数弱+个股强 < 都弱。

### 3. 指数间强弱是核心信号

开盘预测 / 复盘必须含"指数间强弱"子表（最少 2—3 配对：上证/创业板、沪深300/中证1000、科创50/创业板）。强弱反向时必须写"需要警惕"。

### 4. 涨幅榜要标注属性

每只至少标 1 个：估值分位 / 流通市值 / 换手率 / 涨停性质。主题/情绪属性的涨停不能等同基本面改善。

### 5. 资源 / 周期方向三要素

外盘商品价 + A 股竞价强度 + A 股板块量能。**A 股板块量能**最关键。

### 6. 数据接口不完整时，宁少勿假

0 / 空字符串 / 停牌不能当正常值。明确标"未取得"或"接口未推送"。

### 7. 预测 → 兑现表必做

每次复盘含至少 3—5 条量化对照（点数、涨跌幅、振幅），分"✅ 正确"+"❌ 偏差"两栏，偏差项给修正方案。

### 8. 操作按情景分支

偏强 / 震荡 / 转弱三档，每档给触发条件 + 操作动作。通用原则只作补充。

## 流程层经验

### A. 先查接口字段含义，再写代码

沙盒接口字段含义不显然（集合竞价全 0、停牌返回字符串、域名迁移）。先看原始字符串 / 浏览器抓包再写上层逻辑。

### B. 报告三段：事实 / 判断 / 教训

- 事实 = 来自接口的数字
- 判断 = 明确结论
- 教训 = 修正方案

### C. 交付件 vs 开发态分开

- 交付件：`/var/minis/shared/股票/`
- 开发态：`/var/minis/workspace/` 或 `skills/<name>/scripts/`

### D. 接口 0/空 的处理规范

```python
val = response.get("open")
if val is None or val == 0 or val == "":
    report.write("开盘价未取得（接口未推送）")
else:
    report.write(f"开盘价 {val}")
```

### E. 长报告每章节顶部一句小结

先给结论再展开，便于扫读和引用。
